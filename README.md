# WLchek — WhiteList Checker + обход белых списков

Android-приложение, которое проверяет, включена ли фильтрация мобильного интернета
до «белого списка», и умеет **обходить** эту фильтрацию — как клиент и как выходная
нода — на базе ядра [OpenFlux](https://github.com/p1neappleXpress/OpenFlux)
(транспорт Яндекс.Телемост).

Форк приложения [ksmolanin/WhiteListCheker](https://github.com/ksmolanin/WhiteListCheker).

## Как это работает

Встроенное ядро OpenFlux гоняет IPv4-трафик через медиаканал конференции Телемоста:
клиент поднимает локальный VPN и отправляет пакеты в конференцию, а устройство-нода
принимает их и выпускает в интернет. Никаких VDS и root не требуется — нужна только
ссылка на конференцию и общий ключ шифрования.

## Что нового в 3.0

Полный список — в [CHANGELOG.md](CHANGELOG.md). Коротко:

- **Обход (VPN-клиент)** на ядре OpenFlux: режимы «весь трафик» и «только выбранные сайты»,
  выбор приложений, внешний IP, состояние кнопки питания в реальном времени.
- **Выходная нода**: устройство раздаёт интернет другим. Раздать можно **уже добавленное
  подключение** — без повторного ввода настроек; если подключений нет, появляется кнопка
  «Добавить ноду» с полями «конференция + ключ».
- **QR-код ноды** рисуется ядром, есть «Поделиться ссылкой» и «Копировать ссылку».
- **Добавление подключения — только сканированием QR** (ручной ввод и импорт файлов убраны).
- **Честная проверка при включённом VPN**: вместо ложного результата показывается
  предупреждение, что тестер соврёт про белые списки, с кнопкой принудительного замера.
- Починены edge-to-edge отступы, поворот экрана и фоновые проверки.

## Интерфейс

Интерфейс переписан с нуля: вместо нативных XML-экранов (`activity_main.xml`,
`DrawerLayout`, радиокнопки, `ChartView`) — WebView-стек (`assets/index.html`, `app.js`,
`bypass.js`, локальный Tailwind внутри APK, работает офлайн) и мост `window.Bridge` в Kotlin.

- Три вкладки с нижней навигацией: «Проверка», «Обход», «Настройки».
- Главный экран: облачко-статус с цветом вердикта, большая круглая кнопка, чипы трафика
  и времени, две колонки сайтов.
- **Добавление и удаление сайтов прямо из пинговалки** — «+» в шапке колонки открывает
  модальное окно со списком, полем ввода (валидация домена, защита от дублей) и удалением
  с анимацией.
- Статусы каждого домена в реальном времени: `OK` / `RESET` / `--` / `STOP`.
- Экраны обхода: «Клиент / Выходная нода», кнопки питания с индикацией, нижние шторки
  со свайпом, выбор приложений.

### Что вырезано из интерфейса

Посчитал лишним для такого приложения:

- экран статистики с графиком (`ChartView`, `StatisticsActivity`) — история проверок
  по-прежнему пишется в базу, но экрана с графиком нет;
- настройки окна по времени: пресеты 15/20/45/60 минут и часы «с / по»;
- спиннер «сайт разработчика» в футере.

## Установка

Скачайте `app-release.apk` из раздела Releases и установите на Android 8.0+ (API 26).

## Как пользоваться

### Проверка белых списков
Круглая кнопка на главном экране. Проверка идёт по мобильной сети (Wi-Fi игнорируется).
Списки доменов редактируются по «+» в колонках «Белые сайты» / «Обычные сайты».

### Обход (клиент)
1. «Обход» → «Клиент» → «Подключение» → «Добавить» → **«Сканировать QR»**
   (QR показывает нода) — либо вставьте ссылку `openflux://…`, если она есть у вас.
2. Выберите режим: весь трафик или только выбранные сайты/приложения.
3. Круглая кнопка — подключиться.

### Выходная нода (раздача)
1. «Обход» → «Выходная нода».
2. Если подключение уже добавлено — выберите его в «Что раздавать» и нажмите круглую кнопку.
3. Если ничего нет — «Добавить ноду»: вставьте ссылку на конференцию Телемост
   (создаётся на telemost.yandex.ru, вход не нужен), сгенерируйте ключ и сохраните.
   Нода запустится сразу и покажет QR для клиентов.

### Важно про проверку с включённым обходом
Приложение намеренно исключено из собственного туннеля (иначе транспорт Телемоста
зациклился бы), поэтому замер при включённом VPN показывает реальную сеть, а не обход:
тестер скажет «белые списки включены», хотя обход работает. Для настоящей проверки
нужно другое устройство без VPN либо принудительный замер кнопкой в предупреждении.

## Сборка

Требования: JDK 17, Android SDK с `platforms;android-36` и `build-tools;36.0.0`.

```bash
./gradlew assembleDebug
# APK: app/build/outputs/apk/debug/app-debug.apk
```

Подпись релиза берётся из переменных окружения (в CI — из GitHub Secrets):

```
RELEASE_KEYSTORE_PATH
RELEASE_STORE_PASSWORD
RELEASE_KEY_ALIAS
RELEASE_KEY_PASSWORD
```

Если их нет, `assembleRelease` соберётся без релизной подписи и не упадёт.

## Ядро OpenFlux

- `app/libs/openflux.aar` — биндинги gomobile для Android (`arm64-v8a`), собраны из
  пакета `mobile/` проекта [OpenFlux](https://github.com/p1neappleXpress/OpenFlux)
  командой `gomobile bind -target=android/arm64 -androidapi=26 -javapkg=io.openflux.bridge`.
- `app/libs/openflux-sources.jar` — исходники Java-обёртки (`io.openflux.bridge.mobile.Mobile`)
  для читаемости API.

Ядро закрывает всю тяжёлую работу: транспорт Телемост, шифрование, Session-режим,
выходную ноду (l4) и генерацию QR.

## Ограничения

- Пропускная способность канала Телемоста ~2–5 Мбит/с: мессенджеры и сайты — нормально,
  видео — только «как получится».
- Поддерживается только IPv4 и архитектура `arm64-v8a`.
- QR ноды содержит адрес телефона в локальной сети — клиенты должны быть в той же сети
  либо использовать транспорт конференции.
